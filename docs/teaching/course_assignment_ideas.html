Course Assignment Ideas

Database Schema Design & Generation

Two tracks of assignments built around natural-language-to-database generation: one for undergrads who know only schemas and SQL, one for seniors looking for an independent, tangential capstone project.

Track 1Undergrad -- "QA team for an automatic database generator" (4 assignments, SQL/schema only)
Track 2Senior capstone -- standalone, tangential, research-flavored (4 project ideas)
UNDERGRAD TRACK

Framing: "QA Team for an Automatic Database Generator"

Every assignment below only requires schema design and SQL knowledge -- no LLM/agent background needed. Students act as a QA team auditing the output of an automatic database generator.

Why this framing works: it turns familiar SQL/schema exercises into an investigative, gamified activity, while producing genuinely useful adversarial testing on real generator output.

UNDERGRAD -- 1

1Red-Team the Generator

Given

A natural-language specification + the auto-generated relational schema for it.

Task

Find cases where the schema is structurally valid (FKs/PKs fine) but permits semantically nonsensical data -- e.g. a patient discharged before being admitted, an employee who manages themselves, an order shipped before it's placed.

Deliverable

(a) An INSERT sequence that exploits the gap. (b) A CHECK constraint / trigger / temporal constraint that fixes it.

Learning goal: distinguishing structural validity (FK/PK) from semantic validity (business rules). Gamified as a bug bounty, scored by genuine flaws found.

UNDERGRAD -- 2

Schema Evolution Under Changing Requirements

Given

Spec v1 -> generated schema v1. Then spec v2, where requirements changed (new entity, a relationship became many-to-many, a new business rule on a field).

Task

Write the ALTER TABLE migration that evolves schema v1 into a schema satisfying v2 without data loss, plus a rollback script.

Learning goal: schemas as living artifacts, not one-shot designs. Also stress-tests whether generated schemas are evolvable in a sane way.

UNDERGRAD -- 3

Build a SQL-Only Schema Critic

Task

Write a set of information_schema / pg_catalog introspection queries that automatically detect schema violations: missing FKs implied by naming convention (e.g. a customer_id column with no FK), 2NF/3NF violations via functional-dependency heuristics, naming-convention non-compliance, orphan-prone tables.

Deliverable

A runnable SQL-based auto-grader, tested against several auto-generated schemas and a few intentionally bad hand-written schemas as a sanity check.

Learning goal: normalization theory made operational -- a scrappy student-built version of an automated schema-quality metric.

UNDERGRAD -- 4

Data Realism Audit

Given

A schema with declared distribution constraints (e.g. "80% of loans under $50k", "credit score correlates with approval") + a synthetic dataset generated for it.

Task

Write analytic SQL (window functions, percentile_cont, GROUP BY correlation checks) to verify the generated data actually matches the declared statistics.

Learning goal: SQL analytics applied to data quality and statistical validation.

SENIOR CAPSTONE TRACK

Standalone, Tangential, Research-Flavored

Each project below is a legitimate independent contribution -- gradable and potentially publishable on its own -- that happens to be complementary to database-generation research without depending on it.

SENIOR -- 1

Schema-Equivalence Engine

Problem

Two schemas can encode the same conceptual model under renaming or restructuring -- one normalizes address into its own table, the other doesn't; one uses a junction table, the other an array column.

Task

Build a matcher combining graph-isomorphism-style structural comparison with name/embedding similarity that scores "are these the same schema conceptually," not just a textual diff.

Positioning: builds on schema/ontology matching literature -- a legitimate standalone contribution with potential publication value.

SENIOR -- 2

Reverse Pipeline + Round-Trip Consistency Checker

Problem

Validating NL-to-schema generation quality is hard without a gold-standard schema.

Task

Build the reverse direction -- schema + constraints → natural-language description (schema summarization) -- then feed that description back through a schema generator and diff the result against the original schema.

Positioning: round-trip consistency is a known validation technique in translation and compilers, never applied to NL-schema generation before -- a novel, independent evaluation method.

SENIOR -- 3

General Constraint-Satisfying Data Generator

Task

Given schema + constraints (functional dependencies, CHECK constraints, statistical targets), generate valid synthetic rows at scale using constraint propagation or an SMT backend (e.g. Z3).

Deliverable

Benchmark against existing tools (Faker, Mockaroo, SDV) on both correctness (constraint satisfaction rate) and throughput.

Positioning: a real systems project, releasable as a standalone open-source package.

SENIOR -- 4

Cross-Dialect DDL Transpiler with Constraint-Preservation Verification

Task

One abstract schema + constraint specification → DDL for multiple SQL dialects (PostgreSQL, MySQL, SQLite), plus a differential tester proving the constraint semantics (not just syntax) survive translation across dialects.

Positioning: standalone systems project, no NL/AI component at all.
